The scripting language for your game engine.

Lovax reads like Python and runs on a three-tier JIT it carries itself — no LLVM, no runtime to install. Weighted loot tables, signals, coroutines and deterministic RNG are in the language, not bolted on.

use game: pick_weighted, signal, connect, emit
use file

set player = {"name": "Kai", "hp": 100}

set damaged = signal()
fn on_damage(amount):
    player.hp -= amount
connect(damaged, on_damage)
emit(damaged, 25)

set reward = pick_weighted({"common": 80, "rare": 19, "legendary": 1})
say "HP: {player.hp}, you found: {reward}"
file.save_data("save.json", player)
Getting started

Install & run

A prebuilt binary needs no compiler. On Linux or macOS:

shell
curl -fsSL https://raw.githubusercontent.com/uixova/lovax/main/install.sh | sh

Prefer source? Lovax is a single translation unit with zero dependencies — any C++17 compiler builds it:

shell
make                 # optimized ./lovax   (or: make dev / make test)
g++ -std=c++17 -O3 -o lovax src/main.cpp   # no make? one line still works

Then run a file, or start the REPL with no arguments:

shell
lovax hello.lov
lovax                # interactive REPL
lovax --version      # Lovax 1.2.0

Your first program

Blocks are indentation. Strings interpolate with {}. say prints a line.

hello.lov
set name = "world"
say "Hello, {name}!"

# a loop that sums 0..99
set total = 0
for i in range(100):
    total = total + i
say "sum is {total}"        # sum is 4950
→

Identifiers are full UTF-8, so oyuncu_adı is first-class and len("şey") is 3 — counted by code point, not byte.

Language tour

Variables

set defines a new variable; a bare name updates an existing one. Assigning a name that was never defined is an error — so a typo can't quietly introduce a new binding, and closures update outer counters with no ceremony.

variables.lov
set speed = 10        # DEFINES a new variable
speed = 20            # UPDATES the existing one
speed += 5            # compound: += -= *= /= //= %=

score = 1             # ERROR: 'score' is not defined (typo protection)
Language tour

Types & operators

Numbers are exact 64-bit integers and 64-bit floats. Division is the one place Lovax deliberately differs from C: / is true division (always a float) and // is floor division — the same split Python 3 and Lua 5.4 make, so 1 / 3 is never 0.

TypeExampleNotes
int42, 0xFF, 1_000_000exact 64-bit
float3.14, 2.5e-364-bit, scientific notation
string"hi", """multi\nline"""UTF-8; indexed by code point
bool / nulltrue, false, null
list[1, "two", [3]]negative indexing, + joins
tuple(x, y)fixed, immutable
map{"k": 1}insertion-ordered; player.hp
rangerange(0, 10)lazy, allocates nothing
operators.lov
say 7 / 2        # 3.5   — true division, always a float
say 7 // 2       # 3     — floor division (toward -inf)
say -7 // 2      # -4
say 7 % 2        # 1     — floor modulo:  (a // b) * b + a % b == a
say 2 ** 10      # 1024  — power (right-associative)

say [1, 2] + [3]         # [1, 2, 3]
say "cat" in "concat"    # true
say 4 in range(0, 10, 2) # true

Comparison is deep: [1,[2]] == [1,[2]] is true. Logic (and or not) short-circuits, and truthiness follows Python — null, false, 0, "", [], {} are falsy.

Null safety

?. reads a field only when the value isn't null (otherwise the whole chain is null), and ?? supplies a fallback for a null — together they replace a pile of guards.

null-safety.lov
set weapon = player?.equipped?.name ?? "bare hands"

set x = null
say x ?? "fallback"          # fallback
say has(map, "key")         # test a map key without throwing
Language tour

Control flow

if / else if / else, while, and for … in over any iterable — a range, list, string, or map's keys. break and continue work as you'd expect, and a one-line ternary is an expression.

control.lov
set hp = 72
if hp > 66:
    say "healthy"
else if hp > 33:
    say "hurt"
else:
    say "critical"

set label = "low" if hp < 20 else "ok"    # ternary expression

for item in ["sword", "shield", "potion"]:
    say item

set n = 0
while n < 5:
    if n == 3:
        break
    n += 1

Match

match tests a value against patterns — several per arm, with _ as the catch-all.

match.lov
match state:
    "running":
        say "active"
    "paused", "waiting":     # multiple patterns share an arm
        say "idle"
    _:                       # wildcard
        say "unknown"
Language tour

Functions

Declared with fn. They're first-class values, close over their scope, take default parameters, and return with return (or null by default). Wrong argument counts are errors — arity is strict.

functions.lov
fn heal(target, amount = 10):        # default parameter
    return "{target} +{amount} hp"
say heal("hero")                     # hero +10 hp
say heal("hero", 25)                 # hero +25 hp

fn make_counter():
    set n = 0
    fn tick():
        n += 1            # closes over n, updates it
        return n
    return tick

set next = make_counter()
say next()   # 1
say next()   # 2

Anonymous & arrow

Functions are values, so they pass into higher-order builtins like filter and sort. A single-expression body can use the arrow form.

lambdas.lov
set is_even = fn(n):
    return n % 2 == 0
say filter([1, 2, 3, 4], is_even)    # [2, 4]

set double = fn(x) -> x * 2          # arrow: single expression
say double(21)                       # 42
Language tour

Structs & enums

A struct groups typed fields with methods; this is implicit. Fields are unboxed inline values, so an entity.x update allocates nothing — the property that makes entity loops fast.

entity.lov
struct Player:
    hp = 100
    name = "hero"
    fn hurt(amount):          # 'this' is implicit
        this.hp -= amount
    fn status():
        return "{this.name}: {this.hp} hp"

enum State: IDLE, WALK, ATTACK

set p = Player(80, "Aria")
p.hurt(30)
say p.status()                # Aria: 50 hp
say State.ATTACK              # 2
Language tour

Errors

try / catch / finally, and throw for your own. finally always runs — even when a return or break leaves the block.

errors.lov
fn load(path):
    try:
        return file.load_data(path)
    catch e:
        say "could not load: {e}"
        return {}
    finally:
        say "load attempt finished"
!

Runtime errors are located and readable — [Runtime Error] line 4: division by zero — and an uncaught error exits non-zero, so scripts fail loudly, never silently.

Language tour

Coroutines

Cooperative coroutines drive AI, dialogue, and frame-spread work. spawn a function, resume it, and yield values back — resume can pass a value into the paused yield.

coroutines.lov
fn patrol(start):
    set n = start
    while true:
        yield n              # hand a step back to the caller
        n += 1

set guard = spawn(patrol)
say resume(guard, 10)        # 10
say resume(guard)            # 11
say co_status(guard)         # suspended

Modules & the standard library

Built-in modules stay out of your scope until you use them, so nothing is shadowed by accident. Third-party packages install reproducibly, pinned by commit.

game

weighted picks, signals/events, easing, timers, deterministic RNG

file

read/write text, JSON save-data, paths

net

TCP/UDP sockets — servers, clients, LAN & VPS

os · regex

arguments & environment; a self-contained regex engine

shell
lovax install someuser/inventory@v1.2.0   # version-pinned in lovax.lock
lovax --sandbox --allow-net app.lov       # untrusted code: net yes, disk/env no

The capability sandbox is Deno-style: a sandboxed run gets nothing until you grant it, so you can run code you don't fully trust.

Runtime

Performance

Lovax compiles to bytecode on a computed-goto stack VM, then lifts hot loops to native x86-64 through a three-tier JIT — a register allocator, a tracing compiler, and an always-correct template fallback — all written from scratch, no LLVM, no DynASM.

Two levers make game loops fast: struct fields are unboxed inline values, and allocation sinking scalar-replaces per-frame temporaries — a tmp = [i, i+1, i+2] built and read each iteration never reaches the heap. The interpreter is always the oracle: every tier is verified bit-identical to it.

Runtime

Embedding

Lovax is built to be hosted. A C++ façade and a stable C ABI (lovax.h) let an engine register native functions, expose owning userdata with finalizers, and hold values as roots across collections — the bridge a game engine binds its systems through.

host.cpp
Lovax vm;
vm.registerFn("engine_time", [](Args a){ return Value::number(now()); });
vm.run("say \"frame at {engine_time()}\"");

FFI is gated behind --allow-ffi and denied under the sandbox, so embedding never widens the trust boundary by accident.

Runtime

Ship a single binary

Because the interpreter is already a small static binary, a whole Lovax program — net and all — bundles into one self-contained executable. Your players run it with nothing else installed.

shell
lovax bundle game.lov -o game
./game arg1 arg2      # no Lovax install; argv reaches the app via os.args()

The same model behind Deno compile and Bun --compile, natural here because there was never a runtime to ship separately.
